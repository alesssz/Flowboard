# Flowboard — notes for AI assistants

A real-time collaborative kanban board (boards, columns, draggable cards, live updates between users). One pnpm workspace: a React 19 / TypeScript / Vite single-page app with TanStack Query (`apps/web`) and a Node.js 24 / Express 5 / TypeScript API on PostgreSQL with Prisma 7 (`apps/api`), sharing types through `packages/shared` (`@flowboard/shared`). Start from [README.md](README.md); the package READMEs ([apps/web](apps/web/README.md), [apps/api](apps/api/README.md)) describe each side.

## Running things

- **pnpm only**, from the repository root; the version is pinned by `packageManager` in `package.json`. Never mix in `npm install` or `yarn`: they would ignore the workspace and the lockfile.
- Everyday scripts, run in every package that defines them: `pnpm dev`, `pnpm build`, `pnpm typecheck`, `pnpm lint`, `pnpm test`. One package only: `pnpm --filter @flowboard/api <script>`.
- Ports: the web app on **5873** (`strictPort`), the API on **3700** (`PORT` overrides it) and on `127.0.0.1` only (`HOST`), PostgreSQL on **6132**, Prisma Studio on **6255**: the usual ports plus 700, to run beside projects left on the defaults. In development Vite proxies `/api/*` to the API, so the browser sees a single origin and CORS is not involved.
- The `Makefile` mirrors the scripts and adds setup, Git and cleanup targets (`make help`). It must run from PowerShell (where Make uses `cmd.exe`), Git Bash and zsh: every recipe line a single `pnpm`, `git` or `node` command, argument checks with Make functions (`$(if …,,$(error …))`), anything longer a script in `scripts/`. A new pnpm script gets its target, with a `##` description.
- **Database**: PostgreSQL in Docker (`compose.yaml`), started with `pnpm db:up`; the API reads `DATABASE_URL` from `apps/api/.env`. A change to `apps/api/prisma/schema.prisma` comes with its migration (`pnpm db:migrate --name …`), committed together. The Prisma client is generated into `apps/api/src/generated/` (gitignored) by the API's `dev`, `build`, `typecheck` and `test`, so only the tests need a database, in CI too. The API's tests (Vitest and Supertest, `apps/api/test/`) run on their own database, `flowboard_test`, emptied before each test; a change to a route comes with its tests.
- **`pnpm dev` does not type-check**: tsx and Vite only strip types. `pnpm check` (typecheck, lint, build: the CI's checks) must pass before a commit; branches reach `main` with `pnpm merge:main`, through a pull request merged once CI passes.
- Dependency install scripts are blocked by pnpm unless allowlisted in `pnpm-workspace.yaml` (`allowBuilds`). Add an entry only for a package whose script is understood and needed.
- Developed on Windows and macOS: the docs write commands for PowerShell. On Windows, PowerShell 5.1 prepends a UTF-8 BOM to text piped into a native program, so never pipe JSON to `gh` or `node`: write it to a file without a BOM (`[IO.File]::WriteAllText($path, $json)`) and pass the file (`gh api … --input $path`).
- `.env` files hold secrets: never read or print them; new variables are documented in a committed `.env.example`.
- **CI and security** ([docs/ci-and-security.md](docs/ci-and-security.md)): GitHub runs `ci.yml` (typecheck, lint, build; the API's tests, against a PostgreSQL service container) on every push and `audit.yml` (`pnpm audit`) weekly and on dependency changes; both share `.github/actions/setup`. Workflows use **only GitHub's own actions**, pinned to a full commit hash with the release in a comment, with `permissions: contents: read` and `persist-credentials: false`. A new action, permission or secret is a decision to document there first. An advisory is fixed (update, or `overrides` in `pnpm-workspace.yaml` with a comment saying why and when to remove it), never silenced; the one exception is an advisory with no fixed release, reached only through development tools, listed by ID in `auditConfig.ignoreGhsas` with the same kind of comment. `pnpm github:check` compares the repository's settings on GitHub with the documented ones (read-only, needs `gh`).
- **Application security** ([docs/security.md](docs/security.md)): the threats the API covers, each with its defence and its test, and what is not covered yet. A change that adds or weakens a defence updates that page; `apps/api/src/security.ts` runs before every route. Board, column, card, comment, label, member and invitation routes need a session (`requireSession`, mounted in `app.ts` per path); every query behind them filters on `memberOf(userId)`, and every write on the role it needs (`editorOf`, `ownerOf`, with `refuseByRole` for the `403`; `src/boards/access.ts`): a new route or resource does the same, with its cases, and the least role it needs, in `test/permissions.test.ts`.

## Code conventions

- TypeScript `strict` plus `noUncheckedIndexedAccess`; `verbatimModuleSyntax` (type-only imports use `import type`); `erasableSyntaxOnly` (no `enum` or `namespace`: string-literal unions instead).
- API: ESM with `module: nodenext`; relative imports carry the `.ts` extension, rewritten to `.js` by `tsc` (`rewriteRelativeImportExtensions`). Every route lives under `/api` and every response with a body, errors included, is JSON (a `DELETE` answers `204` with none). Request bodies are checked with `parseBody(schema, req.body)` (`src/validation.ts`) against the schemas in `@flowboard/shared/schemas`. `app.ts` builds the app, `index.ts` starts it.
- Web: components in PascalCase, props typed with `interface XxxProps`, event handlers named `handleXxx` and the props that receive them `onXxx`, multi-shape state modelled as discriminated unions, CSS class names in BEM.
- Shared: request and response bodies are typed once in `@flowboard/shared` and imported with `import type`; request types come from the Zod schemas (`z.input`). The package has no build step: Vite, tsx and Node 24's type stripping run its sources, so they stay erasable TypeScript. The schemas are only in `@flowboard/shared/schemas`, so the web app never bundles Zod: the main entry point keeps no runtime Zod import.
- Semicolons, single quotes.

## Working rules

- **Everything in the repository is in English**: code, comments, docs, UI text, commit messages.
- **Comments are functional and short**, for a developer who knows the stack: a constraint, an edge case, a non-obvious reason, code elsewhere that must change together. No explanations of the language or the framework, no history ("used to", how a bug was found, branch names: that is in the commits), and no pointers to docs or READMEs: background and rationale belong in the READMEs and `docs/`. Each source file opens with a one-line header saying what it is for. A test's name states its scenario; files generated by a tool keep their generated shape, with a comment only on what was changed.
- **A change updates the docs it touches in the same commit**: the root README (status, stack, setup, scripts, troubleshooting, roadmap), the package READMEs (scripts, endpoints, environment variables, structure), `docs/`, this file.
- **Docs read as a well-kept project, not a course**: setup, commands, configuration, decisions and known problems, written for someone who will run or maintain the project. A problem actually met goes in the root README's Troubleshooting table (symptom, then fix). No tutorials, no explanations of the stack itself.
- **Backlog** ([docs/backlog.md](docs/backlog.md)): one entry per point, IDs never reused, the entry deleted by the commit that finishes it. The README's Roadmap holds the directions.
- **A branch per task** from `main` (`feat/…`, `fix/…`, `docs/…`, `chore/…`); commit messages follow [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`).
- Git identity: the GitHub noreply address only. `.githooks/pre-commit` refuses any other identity (active after `git config core.hooksPath .githooks`).

## Working on a task

- **Before handing over**, check the comments and docs the task touched against the rules above, and run `pnpm check`. Servers started to collect real output are stopped afterwards, with ports 3700 and 5873 free again.
